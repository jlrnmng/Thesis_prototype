                           1. DATA INGESTION OVERVIEW
================================================================================

The Hirely system implements a multi-modal data ingestion pipeline that handles:
- Resume documents (PDF, DOCX, DOC, TXT formats)
- Job descriptions (text input from admin interface)
- User profiles and application data
- Metadata and classification information

PRIMARY DATA SOURCES:
┌─────────────────────┬──────────────────┬─────────────────────────────────┐
│ Data Type           │ Format           │ Ingestion Method                │
├─────────────────────┼──────────────────┼─────────────────────────────────┤
│ Resume Files        │ PDF, DOCX, TXT   │ File upload + text extraction   │
│ Job Descriptions    │ Text             │ Web form input                  │
│ User Profiles       │ Form Data        │ Registration/profile updates    │
│ Application Data    │ Relational       │ Database transactions           │
│ Vector Embeddings   │ 384-dim vectors  │ ChromaDB storage                │
└─────────────────────┴──────────────────┴─────────────────────────────────┘

================================================================================
                           2. DATA INGESTION PROCESS
================================================================================

2.1 RESUME INGESTION WORKFLOW
-----------------------------

Step 1: File Upload
- Users upload resume files through the web interface
- Supported formats: PDF (PyPDF2), DOCX (python-docx), DOC (mammoth), TXT
- Files stored in secure upload directory with unique filenames
- Maximum file size: 10MB per file

Step 2: Text Extraction
- Multi-format text extraction using specialized libraries
- PDF extraction: PyPDF2 library for text content
- DOCX extraction: python-docx for Word documents
- TXT extraction: Direct file reading with encoding detection

Step 3: Initial Processing
- Raw text cleaning to remove extraction artifacts
- Basic formatting normalization
- Privacy-sensitive information masking
- Text validation and error handling

Step 4: Database Storage
- Extracted text stored in Application.resume_text field
- Original file path stored in User.resume field
- Metadata tracking (file size, extraction timestamp)

2.2 JOB DESCRIPTION INGESTION
-----------------------------

Step 1: Admin Input
- Job administrators input job descriptions via web forms
- Required fields: Role title, description, requirements
- Optional fields: Cluster ID, expiration date

Step 2: Validation
- Input sanitization and XSS protection
- Required field validation
- Content length restrictions (max 10,000 characters)

Step 3: Storage
- Direct storage in Job table with relational integrity
- Creator tracking (admin user ID)
- Timestamp recording for audit trails

2.3 VECTOR EMBEDDING GENERATION
------------------------------

Step 1: Text Preprocessing (detailed in Section 4)
- Comprehensive NLP preprocessing pipeline
- Technical term standardization
- Privacy information removal

Step 2: Embedding Generation
- SentenceTransformer model: all-MiniLM-L6-v2
- 384-dimensional dense vectors
- Semantic similarity preservation

Step 3: ChromaDB Storage
- Vector database storage with metadata
- Collection-based organization (resumes, jobs)
- Automatic indexing for similarity search

================================================================================
                        5. PRE-PROCESSING STEPS IN DETAIL
================================================================================

5.1 STEP 1: BASIC CLEANING
--------------------------

Purpose: Remove PDF/Word extraction artifacts and normalize basic formatting

Operations:
• Unicode normalization (bullets: •, dashes: -, quotes: ', ")
• Non-printable character removal (control characters)
• Excessive whitespace elimination
• Line break normalization

BEFORE:
```
John Doe•Software Engineer
📧john.doe@email.com|📱(555)123-4567


EXPERIENCE
••Senior Software Engineer
```

AFTER:
```
John Doe • Software Engineer
[EMAIL] | [PHONE]

EXPERIENCE
• Senior Software Engineer
```

5.2 STEP 2: STRUCTURE NORMALIZATION
-----------------------------------

Purpose: Standardize document structure while preserving semantic meaning

Operations:
• Section header standardization (EXPERIENCE, EDUCATION, SKILLS)
• Bullet point normalization
• Consistent spacing between sections
• Paragraph structure preservation

PRESERVE_STRUCTURE = True:
```
EXPERIENCE
• Senior Software Engineer at TechCorp (2020-2023)
• Developed web applications using React.js

SKILLS
• JavaScript, Python, Java
```

PRESERVE_STRUCTURE = False:
```
senior software engineer techcorp developed web applications react javascript python java
```

5.5 STEP 5: PRIVACY INFORMATION PROTECTION
-------------------------------------------

Purpose: Remove or mask sensitive personal information

PRIVACY MASKING OPERATIONS:
• Email addresses → [EMAIL]
• Phone numbers → [PHONE]
• Street addresses → [ADDRESS]
• Social security numbers → [SSN]
• URLs → [URL]

BEFORE:
```
Contact: john.doe@email.com, (555) 123-4567
Address: 123 Main St, Anytown, ST 12345
```

AFTER:
```
Contact: [EMAIL], [PHONE]
Address: [ADDRESS]
```

5.6 STEP 6: SPECIAL CHARACTER HANDLING
--------------------------------------

Purpose: Normalize punctuation and special characters consistently

Operations:
• Multiple periods (. . .) → single period (.)
• Multiple exclamations (!!) → single exclamation (!)
• Standardize bullet points (•, ▪, ‣) → (•)
• Remove standalone special characters

5.7 STEP 7: FINAL CLEANUP AND VALIDATION
-----------------------------------------

Purpose: Final text normalization and quality assurance

Operations:
• Whitespace normalization (multiple spaces → single space)
• Proper punctuation spacing
• Text trimming and validation
• Length validation (minimum/maximum thresholds)

8.2 DATABASE SCHEMA
-------------------

RELATIONAL DATABASE TABLES:
```sql
-- Users table
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    first_name VARCHAR(80) NOT NULL,
    last_name VARCHAR(80) NOT NULL,
    email VARCHAR(120) UNIQUE NOT NULL,
    password_hash VARCHAR(128),
    resume VARCHAR(255),
    is_admin BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Jobs table
CREATE TABLE jobs (
    id INTEGER PRIMARY KEY,
    role VARCHAR(100) NOT NULL,
    description TEXT NOT NULL,
    cluster_id INTEGER,
    is_active BOOLEAN DEFAULT TRUE,
    created_by INTEGER NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (created_by) REFERENCES users(id)
);

-- Applications table
CREATE TABLE applications (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,
    job_id INTEGER NOT NULL,
    cluster_id INTEGER,
    resume_text TEXT NOT NULL,
    submission_date DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (job_id) REFERENCES jobs(id),
    UNIQUE(user_id, job_id)
);
```
